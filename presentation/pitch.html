PROBLEMA & OPORTUNIDAD

El analista antifraude pierde tiempo en lo obvio

  • 15.000+ siniestros mensuales en una aseguradora típica de Ecuador.
  • Solo 6–8% son posibles fraudes, pero hay que revisarlos todos.
  • Detección manual = experiencia del analista + cruce mental de variables + reglas en Excel.

Consecuencias

Pérdida directaCosto indirecto
Pagos a fraudes que pasan filtroTiempo del analista en casos verdes
Reservas sobreestimadasAtraso en pagos legítimos
Riesgo regulatorio SBSFrustración del cliente honesto
"Si un analista revisa 100 casos al día y el 92% son verdes, está perdiendo 7 horas diarias en casos que un sistema podría descartar en 1 segundo."
2 · Problema y oportunidad
SOLUCIÓN PROPUESTA

Un sistema HÍBRIDO de 3 capas

1 · Reglas determinísticas — 7 críticas (RF-01..07) + 14 señales puntuadas
Trazable y auditable. Cada caso ROJO/AMARILLO se justifica con regla + evidencia.
2 · Modelo XGBoost en Azure ML — registrado como achachai-fraude-xgb v2
Captura patrones implícitos. AUC-ROC 0.94. Top features alinean con las señales del reto.
3 · Agente conversacional GPT-5-mini en Azure AI Foundry — 8 tools con DuckDB
El analista pregunta en lenguaje natural. Responde con tabla + evidencia + acción sugerida.

Cada caso recibe

  • Score 0–100 + semáforo VERDE / AMARILLO / ROJO
  • Reglas activadas con citas concretas (id, fechas, montos, proveedor)
  • Explicación natural generada por GPT-5-mini, lenguaje no-acusatorio
  • Top 5 features SHAP del modelo para interpretabilidad

LIMITACIONES & ÉTICA

Lo que NO hace este sistema

  • ❌ NO rechaza siniestros automáticamente
  • ❌ NO toma decisiones de pago
  • ❌ NO acusa a un cliente de fraude
  • ❌ NO sustituye al analista humano
  • ❌ NO procesa datos personales reales (dataset sintético)

Salvaguardas implementadas

  • System prompt prohíbe acusar
  • Test automático verifica lenguaje no acusatorio
  • Toda alerta requiere revisión humana
  • Score es input al analista, NO output al cliente
